# Оформление интерфейса

Версия 0.10.2. Общие правила языка — [ui-language.md](ui-language.md).

## Настройки установки

Администратор открывает «Настройки» → «Оформление». Доступны синий, бирюзовый,
зелёный, фиолетовый, бордовый и графитовый варианты, каждый со светлым или тёмным
режимом. Предпросмотр ограничен своей карточкой. «Сохранить оформление» применяет
настройки установки; «Вернуть стандартное оформление» заполняет форму стандартными
значениями, которые тоже нужно сохранить. Произвольные цвета не вводятся: проверенные
сочетания сохраняют читаемость текста.

Настройки хранятся в PostgreSQL, а не в браузере. Их используют все роли и страница
входа. Открытый сеанс получает изменения при возвращении к окну и переходе между
страницами. Непрерывного опроса сервера нет. При недоступности настроек приложение
сохраняет последнее полученное оформление; при первом открытии используется стандартное.
На странице настроек доступны сообщение об ошибке и повторная загрузка.

`GET /api/v1/settings/appearance` публично возвращает только `palette`, `mode`, `version`.
`PATCH` требует действующего сеанса, права `MANAGE_CONFIGURATION`, проверки Origin,
CSRF и актуальной версии. Изменение и запись аудита выполняются в одной транзакции.
Устаревшая версия получает 409, неизвестные значения и лишние поля — 422.
В журнале аудита палитры и режимы имеют русские подписи. Произвольный CSS, HTML,
адреса ресурсов и секреты этим API не принимаются. Политика CSP не ослаблена.

Миграция `0010b` добавляет три поля к установке. Старые установки получают синий
светлый вариант и версию 1. Пользователи, события и уведомления сохраняются.
Откат миграции удаляет только новые настройки оформления; перед обновлением нужна
резервная копия, согласно обычной процедуре проекта.

## Общие правила компонентов

- Цвета фона, текста, рамок, фокуса и семантических состояний задаются переменными
  в `frontend/src/styles.css`. Новые компоненты используют эти переменные.
- Основная кнопка и поля — от 44 пикселей в высоту; компактная кнопка — 40.
  Между действиями — от 8 пикселей, в группах действий — 10. Группы переносятся
  на следующую строку. Для действий таблиц предусмотрена достаточная ширина.
- `Field` связывает постоянную подпись, подсказку и ошибку с полем через доступные
  атрибуты. Заполнитель не заменяет подпись. Флажки и переключатели имеют нажимаемые подписи.
- Таблицы прокручиваются внутри контейнера и доступны с клавиатуры; горизонтальная
  прокрутка всей страницы не требуется. На мобильном экране меню открывается кнопкой.
- Цвет статуса дополняется русским текстом. Для ошибок, успеха и предупреждений
  используются отдельные семантические цвета, не зависящие от основной гаммы.
- Фокус виден, поддерживаются уменьшение анимации и системные контрастные цвета.
  Нет внешних шрифтов, картинок и библиотек оформления.
- Даты расписания и фильтров вводятся в формате «ДД.ММ.ГГГГ ЧЧ:ММ»; время сводки —
  «ЧЧ:ММ». Ввод и пояснения не зависят от языка встроенных календарей браузера.

Ориентиры проверки — [WCAG 2.2](https://www.w3.org/WAI/WCAG22/quickref/):
контраст обычного текста не ниже 4,5:1, заметность фокуса, постоянные подписи,
клавиатурное управление, перенос содержимого и размер целей управления.
Эти проверки не заменяют полную независимую оценку соответствия WCAG.

## Учёт всех полей

[ui-field-inventory.json](ui-field-inventory.json) содержит 125 мест объявления
элементов `input`, `select`, `textarea` в 19 файлах, включая условные ветви. Для
каждого указаны файл, строка, тип, ссылка на подпись, подсказку и заполнитель.
Это количество объявлений в коде: один флажок в цикле может создавать несколько
полей на экране. Обновление реестра: `cd frontend && node scripts/inventory-ui.mjs`.
Скрипт завершается с ошибкой, если не найдена ссылка на подпись.

| Область | Поля и состояния проверки |
| --- | --- |
| Вход, пароль | Имя пользователя, пароль, текущий/новый/повтор пароля, ошибки и завершение сеанса |
| События | Все семь фильтров, периоды, курсорная навигация, карточка, история поступлений и действия |
| Источники | Название, описание, включение, общие/собственные настройки повторов, окно и сравниваемые поля |
| Определение источника | Название, источник, приоритет, включение, условия/группы, назначения, история версий |
| Условия | Поле, имя заголовка/дополнительного поля, сравнение, текстовое/числовое значение, адаптер, важность/источник, регистр |
| Обработка | Все пять действий, область применения, категория, тип, метки, канал, задержка, дата, сводка и эскалация |
| Тестовое событие | SMTP/REST, источник, важность, отправители, получатели, тема, текст, заголовки, дополнительные значения всех типов |
| Каналы | Все три типа, адрес, порт, защита, авторизация, получатели, секрет, шаблон, включение, настройки адаптеров, тестовая отправка |
| Шаблоны | Название, тип, тема, текст, оформление письма, вставка переменных, тестовые значения, предпросмотр и история |
| Эскалация | Название, описание, включение, каналы шагов, сроки, подтверждение/решение/подавление события |
| Сводки | Название, описание, включение, канал, шаблон, время, пояс, период, отбор, источники, важность, ожидание, пустая сводка |
| Уведомления | Фильтр состояния, доставка/попытки, ошибки, подтверждения повтора и отмены |
| Пользователи | Создание/изменение, имя, отображаемое имя, пароль, роль, активность, диалог и ошибки |
| Аудит | Фильтр действия, изменения, русские значения оформления и ролей |
| Состояние системы | Состояния компонентов, очереди, ошибки, узкая/широкая компоновка |
| Оформление | Шесть вариантов гаммы, два режима, предпросмотр, сохранение, восстановление стандартных значений, конфликт версии |

Общие стили применяются ко всем перечисленным объявлениям.
Браузерный сценарий
`ui-review.spec.ts` дополнительно обходит страницы и ветви редакторов на ширине
1440, 768, 375 и 320 пикселей, проверяя подписи, связи подсказок, повторяющиеся
идентификаторы, размеры полей, расстояние между кнопками и переполнение страницы.
`appearance.spec.ts` проверяет палитры, контраст, клавиатуру, отдельный браузер,
конфликт версии и запрет изменения для наблюдателя. Рабочие сценарии остальных
страниц проверяются существующим набором интеграционных тестов.

В обходе форм доступность адаптеров подменяется только в ответе браузерного теста,
чтобы открыть все три редактора без разрешения исходящих соединений. Реальные
отправки в интеграционных сценариях направляются только локальным имитаторам.

## Дополнение этапа 11

Форма сроков хранения использует общий `Field`, адаптивную сетку и явное подтверждение
удаления. Черновик отдельно отмечается, состояние очистки берётся из сохранённых
настроек. Показатели допускают длинное «Недостаточно данных» и большие счётчики,
не расширяя страницу на экране 320 пикселей. Реестр обновлён до 119 объявлений.


## Дополнение: подключение источников

Добавлены инструкция REST/SMTP и управление ключами приёма, пояснения всех
четырёх каналов. Реестр: 125 объявлений полей в 19 файлах, без полей без подписи.
Новый раздел входит в общий обход четырёх ширин; отдельно проверены создание,
скрытие и отзыв ключа, смена/сохранение/удаление SMTP-пароля и запрет управления
для оператора и наблюдателя.
