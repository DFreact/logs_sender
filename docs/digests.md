# Сводки

Этап 10 реализован в версии 0.10.0. [Фактический контракт, API и ограничения](digest-runtime.md).
Ниже сохранено исходное архитектурное описание.

DigestDefinition задаёт имя, фильтр событий, канал, шаблон, локальное расписание,
часовой пояс и период. Для ежедневной сводки в 08:00 рекомендуем окно от
предыдущего планового запуска до текущего: [start, end). Это календарный день
в выбранном часовом поясе; при переходе времени он не обязательно равен 24 часам.
Если выбран режим «Последние 24 часа», использовать ровно 24 часа и явно
описать возможное перекрытие окон при изменении локального времени.

Планировщик фиксирует DigestRun с уникальным definition_id/window_start/end,
снимком версии и одним временем границы. После простоя создаёт пропущенные
окна ограниченными пакетами, не сдвигая границы к времени рестарта. Для
несуществующего локального времени запуск в ближайшее доступное; для
повторяющегося — один раз в первом вхождении. Эти правила показываются в справке.

После завершения нормализации всех поступлений до границы окна обработчик
выбирает EventOccurrence и фиксирует DigestItem идемпотентными пакетами.
Контрольная отметка приёма позволяет отличить необработанные сообщения от
пустого периода. Если обработка задержалась, сводка ждёт и показывает причину;
после настраиваемого предела администратор решает отправить неполную сводку
или дождаться завершения. Поздние результаты не теряются молча.

Сводка содержит число поступлений и отдельных событий, группировки по
источнику и важности, самые частые события, первое и последнее поступление,
счётчики. Считать по историям поступлений внутри окна, не по накопленному
occurrence_count за весь срок жизни события.

После фиксации состава подготовить payload и Notification в одной транзакции.
Повторное исполнение не создаёт второй Notification для того же запуска/канала.
Пустая сводка по умолчанию не отправляется; результат запуска сохраняется.
История состава защищена от очистки до подготовки уведомления. Дальнейшая
доставка использует общую очередь, попытки и правила повторной отправки.
