# Безопасность

Проектные требования; реализованная аутентификация и аудит описаны в
[ADR-005](adr/005-authentication.md).
Остальные требования подтверждаются по мере реализации соответствующих этапов.
В MVP одна команда, но team_id проверяется при доступе ко всем сущностям.
Полную изоляцию арендаторов не заявлять до отдельного аудита.

| Действие | Администратор | Оператор | Наблюдатель |
| --- | --- | --- | --- |
| Смотреть события, уведомления и попытки | Да | Да | Да |
| Подтверждать, решать и подавлять события | Да | Да | Нет |
| Повторять/отменять уведомления | Да | Да | Нет |
| Менять настройки, пользователей, правила | Да | Нет | Нет |
| Смотреть административный аудит | Да | Нет | Нет |
| Смотреть состояние системы и очередь фоновых задач | Да | Нет | Нет |
| Отправлять тестовое уведомление | Да | Нет | Нет |

Проверять права сервером на каждом действии, не только скрытием кнопки.
Первый администратор создаётся локальной командой без поставляемого пароля.
Пароли хешировать Argon2id с параметрами по измерениям установки. Использовать
непрозрачные отзываемые сеансы, HttpOnly/Secure/SameSite cookie, срок действия,
смену идентификатора после входа и защиту CSRF для изменяющих запросов.
Ограничить частоту входа по учётной записи и адресу; ответ не раскрывает
существование пользователя. Ключи REST-приёма отделены от сеансов администратора.

Секреты не включать в код, сборку frontend, журнал или аудит. Ключ шифрования
секретов хранится отдельно от БД и включается в защищённый план восстановления.
В API секрет доступен только на запись; ответ показывает факт настройки.
Аудит хранит маскированные различия и коды действий с русским отображением.

## Webhook и SSRF

Только разрешённые схемы HTTP/HTTPS (HTTPS по умолчанию), хосты, порты и сети
из политики администратора. Запретить userinfo в URL, автоматические
перенаправления, loopback, link-local и адреса метаданных. Локальные корпоративные
адресаты допустимы только через явный список разрешённых сетей/узлов; нельзя
запретить все частные сети и одновременно обещать локальные интеграции.
При каждом подключении проверять все IPv4/IPv6-результаты DNS и фактический
адрес назначения; защититься от DNS rebinding через привязку соединения
к проверенному адресу с корректной проверкой TLS-имени. Ограничить исходящий
трафик на сетевом уровне. Сохранение настроек и тест подключения используют
одинаковую политику. Ответ ограничен размером и не возвращается как сырой HTML.

## Содержимое сообщений и шаблоны

Лимиты тела HTTP, MIME, числа частей, заголовков, вложений, глубины JSON,
регулярных выражений и времени обработки обязательны. Blob не исполнять,
не размещать в корне веб-сервера; скачивание требует прав, Content-Disposition
attachment и защиты от определения опасного типа. HTML очищать по белому
списку, внешние картинки не загружать, предпросмотр изолировать.

Шаблоны: ограниченная Jinja с неизменяемыми словарями разрешённых данных,
StrictUndefined, белым списком фильтров, запретом вызовов/импортов/атрибутов
служебных объектов. Лимитировать время, память и размер результата в отдельном
процессе; одна песочница не является полной защитой. HTML экранируется и
очищается, тема письма защищена от CR/LF-инъекций. Webhook сериализуется
как JSON с проверкой структуры. Обоснование — [ADR-003](adr/003-data-and-templates.md).

Обработчик исключений переводит ошибки в безопасные коды; Pydantic input,
SQL, адреса с паролями и цепочки исключений не попадают в API. Журналы
используют структурированные разрешённые поля и редактирование до записи.
Пользовательские тексты — по [ui-language.md](ui-language.md).

## Поставка

TLS, CSP, запрет встраивания, nosniff, ограниченные CORS и доверенные прокси.
Контейнеры без root, лишних capabilities и доступа к Docker socket; доступ
на запись только к нужным томам. Зависимости и образы фиксируются, обновляются
через проверяемую процедуру с перечнем компонентов. Не использовать внешние
CDN, шрифты, JavaScript и обязательные SaaS во время работы приложения.


## Реализованный приём (этап 4)

Ключ приёма даёт доступ только к приёму и собственным квитанциям; в БД только
хеш. Ключи выдаются на 90 дней и отзываются через локальную консоль установки.
Просмотр события и скачивание требуют пользовательского сеанса и проверки
команды и связи файла с событием. API не принимает файловые пути от пользователя.
SMTP ограничен сетями, получателями, соединениями, размером, частотой и командами;
за пределами явно указанного локального исключения требует STARTTLS.
SMTP AUTH пока отсутствует. [Точные ограничения](ingestion.md).
HTML из сообщений выводится как текст. Все скачивания — attachment/octet-stream,
без исполнения HTML и без встраивания внешних изображений. Повреждённое письмо
остаётся в оригинале, даже если безопасный разбор ограничен.


Сводки (этап 10): все роли читают определения, предпросмотр, историю запусков
и состав. Создание и изменение настроек, продление ожидания и разрешение
неполной отправки доступны только администратору и записываются в аудит.
История не раскрывает параметры подключения канала или ключи операций.
