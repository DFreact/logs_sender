# Автономная установка и обслуживание

Комплект `0.12.2-offline.2` содержит готовые образы приложения 0.12.2,
PostgreSQL и Redis, установщик и инструменты обслуживания. Схема БД — `0012`.
Подготовленная архитектура — Linux x86-64.

Встроенная политика nftables в этом комплекте не используется. Установщик
не создаёт, не применяет и не удаляет правила межсетевого экрана.
Сетевой доступ контролируется внешним МСЭ организации, включая DNS и разрешённые
соединения с корпоративной почтой и MAX. Прикладные проверки адресов, TLS
и прав доступа сохранены. Наличие внешнего МСЭ не проверяется установщиком.

## Требования

На сервере заранее должны быть установлены Python 3.7+, Docker Engine,
Docker Compose v2 с `--wait` и `--pull never`, iproute2 с поддержкой `ip -j`.
Docker должен быть запущен локально в обычном режиме, без rootless.
Установка не скачивает пакеты и образы. Системные инструменты устанавливаются
из доверенного репозитория организации; их пакеты в архив не входят.
Astra Linux 1.7/1.8 требует отдельных испытаний: имеющиеся проверки выполнены на Ubuntu.

## Установка одной командой

Перенесите архив `eventhub-0.12.2-offline.2-linux-amd64.tar.gz` и `SHA256SUMS`
в один каталог. Выполняйте команды последовательно, продолжая только при успехе:

```bash
sha256sum --ignore-missing -c SHA256SUMS
tar -xzf eventhub-0.12.2-offline.2-linux-amd64.tar.gz
cd eventhub-0.12.2-offline.2
sudo ./install.sh
```

Скрипт проверяет комплект, сервер и конфликты подсетей, загружает образы,
создаёт секреты, запускает компоненты и предлагает дважды ввести пароль
первого администратора. Встроенного пароля нет. Параметры по умолчанию:

| Настройка | Значение |
| --- | --- |
| Каталог установки | `/srv/eventhub` |
| Имя проекта Docker | `eventhub` |
| Веб-интерфейс | `http://127.0.0.1:8080` на сервере |
| Приём SMTP | `127.0.0.1:2525` |
| Подсеть | Свободная `/24`, выбранная по сетям Docker и маршрутам узла |
| DNS | Системные настройки Docker |
| Администратор | `admin`, пароль вводится при установке |

Установщик не знает о сетях организации, отсутствующих в таблице маршрутов узла.
При наличии зарезервированных диапазонов укажите согласованную подсеть явно.
Каталог и имя проекта должны быть новыми. Повторный запуск не перезаписывает данные.
После ошибки создания администратора приложение уже установлено: используйте
отдельную команду создания учётной записи ниже, а не повторную установку.

Пример собственных параметров:

```bash
sudo ./install.sh --directory /srv/eventhub --project eventhub \
  --subnet 172.28.40.0/24 --http-port 8080 --smtp-port 2525 \
  --dns 10.20.0.53
```

Замените пример DNS адресом корпоративного сервера. Параметр `--dns` можно повторить.
`--ca-file /путь/ca.pem` подключает корпоративные корневые сертификаты исходящих
каналов; приватные ключи не принимаются. `--skip-admin` допускает установку
без интерактивного терминала с последующим созданием администратора.

Файлы секретов создаются в приватном каталоге установки и точечно монтируются
в нужные контейнеры. База данных и файлы событий хранятся в томах Docker.
Не используйте `down -v` над рабочей установкой.

## Первый вход и сетевой доступ

```bash
sudo docker compose -p eventhub --env-file /srv/eventhub/settings.env \
  -f /srv/eventhub/compose.json exec api python -m app.cli create-admin \
  --username admin --display-name 'Администратор'
```

Эта команда нужна только при пропуске или ошибке создания администратора.
Для доступа с рабочего компьютера можно использовать SSH-туннель:

```bash
ssh -N -L 18080:127.0.0.1:8080 пользователь@адрес-сервера
```

Откройте `http://127.0.0.1:18080`. Постоянная публикация в корпоративной сети
требует HTTPS-прокси и настройки доверенных адресов. HTTP и SMTP по умолчанию
слушают только loopback; удаление встроенной политики не открывает эти порты наружу.

## Изменение настроек действующей установки

Команды выполняются из каталога распакованного комплекта. Для изменения подсети,
портов или DNS используется `configure`; незаданные параметры сохраняются:

```bash
sudo python3 admin.py configure --directory /srv/eventhub \
  --subnet 172.28.41.0/24 --http-port 8081 --smtp-port 2526
```

Команда предварительно проверяет параметры и пересечение подсетей, сохраняет
предыдущую конфигурацию в `configuration-previous-*`, останавливает контейнеры,
пересоздаёт сеть и запускает компоненты. Тома, данные и секреты сохраняются.
На время операции приём событий и интерфейс недоступны. При неудачном запуске
выполняется возврат прежних настроек; если возврат тоже не удался, инструмент
сообщает об этом и оставляет сохранённую конфигурацию для восстановления.

Остальные рабочие параметры, включая разрешённые адреса каналов, меняются
в `/srv/eventhub/settings.env`. После редактирования:

```bash
sudo python3 admin.py start --directory /srv/eventhub
```

Команда применяет параметры окружения при пересоздании затронутых контейнеров.
Не меняйте подсеть вручную в `settings.env`: используйте `configure`.
Не редактируйте `compose.json` и контрольные суммы в `installation.json` вручную.

## Корпоративная почта и MAX

Внешний МСЭ должен разрешать DNS, точный SMTP-сервер с нужным портом и HTTPS
к серверу MAX. Прикладной список разрешений остаётся отдельной защитой от
обращений к произвольным адресам. По умолчанию он пуст: внешняя отправка выключена.
В `settings.env` укажите реальные значения, например:

```dotenv
HUB_OUTBOUND_HOSTS=["mail.corp.example","platform-api2.max.ru"]
HUB_OUTBOUND_NETWORKS=["10.20.0.25/32","<согласованный IPv4 MAX>/32"]
HUB_OUTBOUND_PORTS=[443,465,587]
HUB_MAX_ALLOWED=true
```

Это шаблон: замените имя почты и адреса перед применением. При нескольких адресах
DNS включите все согласованные адреса в список сетей. Нельзя подставлять шаблон
с угловыми скобками как рабочую конфигурацию. Для SMTP на порту 25 явно добавьте 25.
Публичные назначения, кроме фиксированного сервера MAX на 443, по-прежнему
блокируются приложением. Корпоративный SMTP предполагается в частной сети.

Выполните `admin.py start`, затем создайте канал в интерфейсе и задайте SMTP-пароль
или токен MAX. Пароли и токены не помещайте в `settings.env` или командную строку.
Проверка соединения и пробная отправка выполняются из настроек канала.

## Запуск, остановка и перезагрузка

```bash
sudo python3 admin.py stop --directory /srv/eventhub
sudo python3 admin.py start --directory /srv/eventhub
```

У постоянно работающих контейнеров используется `unless-stopped`. После перезапуска
Docker они возобновляются, если не были остановлены явно. Для запуска после
перезагрузки ОС Docker должен быть включён в автозагрузку средствами организации.
Внешний МСЭ должен обеспечивать нужную политику независимо от работы установщика.

## Резервное копирование и восстановление

```bash
sudo python3 admin.py backup --directory /srv/eventhub --output /backup/eventhub-copy
sudo python3 admin.py restore --backup /backup/eventhub-copy \
  --directory /srv/eventhub-restored --project eventhub-restored \
  --http-port 8083 --smtp-port 2528 --subnet 172.28.42.0/24
```

Каталоги копии и новой установки должны отсутствовать. Для копии останавливаются
все компоненты, изменяющие данные; затем возобновляются ранее работавшие компоненты.
Копия содержит БД, файлы, ключ шифрования каналов и рабочие настройки.
Она не зашифрована: храните её на защищённом носителе отдельно от сервера.

Восстановление проверяет контрольные суммы, файлы, версию схемы и идентификаторы
образов. Принимаются копии этого комплекта, а также `0.12.2-offline.1` с той же
схемой и теми же образами. Исходная установка не изменяется. Приём и отправка
после восстановления остановлены; проверьте каналы, затем выполните `start`.

Пароли пользователей и ключ каналов сохраняются; системные секреты создаются
заново, старые сеансы отзываются. Сетевой профиль, DNS и корпоративный CA при
восстановлении задаются заново. Учтите возможные повторы внешней доставки.
Перед переключением остановите приём и обработку на старой установке до создания
окончательной копии: новые события после точки копии не входят в восстановление.

Старые установки со встроенной политикой обслуживаются их исходным комплектом.
Новый установщик не снимает их защиту автоматически. Перенос выполняется через
копию и новую установку. Исторические инструменты политики оставлены в исходниках
для совместимости, но не входят в новый автономный архив и не вызываются им.

## Сборка комплекта

На машине подготовки с проверенными локальными образами:

```bash
python3 scripts/build-offline.py --output /защищённый/путь/комплект
```

Контрольные суммы проверяют целостность, но не заменяют проверку происхождения
или цифровую подпись. Не запускайте неизвестный установочный комплект.
