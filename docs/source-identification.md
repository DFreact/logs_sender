# Источники и правила определения источника

Фактический контракт этапа 5, версия 0.5.0. Настройки доступны администратору
в разделах «Источники» и «Правила определения источника».

## Порядок настройки

1. Создать источник: название, описание, состояние и настройки объединения повторов.
2. Создать правило, выбрать источник и заполнить условия в визуальной форме.
3. При необходимости назначить важность, категорию, тип события и метки.
4. Отправить сообщение через существующий SMTP или REST-вход.
5. Проверить источник в списке событий и применённую версию правила в истории поступлений.

Меньшее число приоритета проверяется раньше. Среди правил с одинаковым
приоритетом порядок стабилен по идентификатору. Первое совпавшее включённое
правило с включённым источником завершает определение. Без совпадения источник
остаётся неопределённым. Отключение источника исключает его правила из обработки,
но сохраняет существующие события. Удаления источников и правил на этом этапе нет.

Правило применяется при нормализации, а не при подтверждении приёма. Сообщение,
ожидавшее обработки, использует актуальную на момент нормализации конфигурацию.
Изменение настроек не переклассифицирует уже обработанные поступления.

## Условия и ограничения

Поддержаны отправитель, получатели, тема, текст сообщения, заголовок письма,
входной адаптер и поле дополнительных данных REST. Для заголовка указывается
его имя, для дополнительных данных — ключ верхнего уровня объекта `metadata`.
Путь к вложенному полю и выполнение программного кода не поддерживаются.

Сравнения: равно, не равно, содержит, не содержит, начинается/заканчивается,
регулярное выражение, наличие значения. Для числового поля дополнительных
данных доступны больше, не меньше, меньше, не больше. Числовая строка не
превращается в число автоматически; логическое значение не является числом.
Строковые сравнения по умолчанию не учитывают регистр; имя заголовка письма
всегда сравнивается без учёта регистра.

Группы «И», «ИЛИ», «НЕ» задаются формой. Отсутствующее значение не совпадает
с обычным сравнением, в том числе отрицательным. Для проверки отсутствия
используется «НЕ» с условием «существует». Для списка достаточно одного
положительного совпадения; отрицательное сравнение требует отсутствия
совпадений во всём списке. Неизвестный результат не превращается в совпадение.

На команду разрешено до 100 источников и 100 правил, включая выключенные.
Приоритет — 0–100 000. Дерево содержит до 100 узлов, корень имеет глубину 0,
максимальная глубина — 3. Группа «НЕ» содержит ровно одно условие.
Строка сравнения — до 500 символов, имя заголовка/поля — до 120.
Категория и тип события — до 120, метки — до 20 значений по 64 символа.
Ограничения приёма и доступного текста остаются из [ingestion.md](ingestion.md).

Регулярные выражения выполняет RE2: ограничение памяти компиляции — 8 МиБ,
кэш — 128 выражений. Синтаксис исключает обратные ссылки и проверки окружения;
повторения не используют перебор с возвратом. См. [контракт RE2](https://github.com/google/re2/blob/main/README.md)
и [допустимый синтаксис](https://github.com/google/re2/wiki/Syntax).
Некорректное выражение отклоняется при сохранении безопасной русской ошибкой.

## История и согласованность

Каждое сохранение правила создаёт неизменяемую версию с автором и временем.
История открывается в интерфейсе, снимок отображается теми же русскими полями,
без технического JSON. Поступление хранит ссылку на применённую версию и снимок
нормализованных значений. Поэтому последующее изменение правила не переписывает
объяснение уже принятого решения.

Изменения источника, правила и общей политики защищены ожидаемой версией:
устаревший запрос получает конфликт, пользователь должен обновить данные.
Изменения записываются в журнал аудита без содержимого входящих сообщений.
Согласованность конфигурации обеспечивает блокировка команды: изменения
эксклюзивны, параллельная нормализация использует совместную блокировку.

## API и права

Все пути имеют префикс `/api/v1` и требуют пользовательского сеанса.
Изменения дополнительно требуют проверки источника запроса и защиты от CSRF.

| Путь | Доступ |
| --- | --- |
| `GET /sources` | Роли с правом просмотра событий |
| `POST /sources`, `PATCH /sources/{id}` | Администратор |
| `GET/PATCH /dedup-policy` | Администратор |
| `GET/POST /identification-rules`, `PATCH /identification-rules/{id}` | Администратор |
| `GET /identification-rules/{id}/versions` | Администратор, страницы по 25 записей |

Список событий поддерживает `source_id` и `unknown_source`. Карточка возвращает
число поступлений, первое/последнее время и историю по 25 записей с параметром
`occurrence_offset`. Правила обработки и симуляция относятся к этапу 6.
