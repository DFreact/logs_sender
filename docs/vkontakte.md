# Уведомления во ВКонтакте

Коннектор `VK` отправляет текстовые уведомления от имени сообщества через
`https://api.vk.com/method/messages.send`, версия API `5.199`. Входящие события
по-прежнему принимаются через SMTP/REST; обратное подключение из интернета,
Callback API и Long Poll для этого выходного канала не нужны.

## Настройка

1. Включите сообщения сообщества и создайте ключ доступа сообщества с правом
   работы с сообщениями. Личный пользовательский токен для этого коннектора
   не подходит.
2. Для личных сообщений получатель должен разрешить сообщения сообщества.
   Для беседы добавьте сообщество в беседу с правом отправки сообщений.
3. Администратор установки разрешает `api.vk.com:443` на внешнем МСЭ и в
   прикладных настройках. В `settings.env` добавьте `HUB_VK_ALLOWED=true`,
   `api.vk.com` к `HUB_OUTBOUND_HOSTS`, все согласованные адреса назначения к
   `HUB_OUTBOUND_NETWORKS` и порт 443 к `HUB_OUTBOUND_PORTS`.
   Существующие разрешения почты и MAX сохраняйте. Затем из каталога **своего**
   установочного комплекта выполните:

   ```bash
   sudo python3 admin.py start --directory /srv/eventhub
   ```

   Это пересоздаёт затронутые контейнеры. По умолчанию отправка во ВКонтакте
   выключена. Без сетевого допуска тип канала виден в списке адаптеров, но
   недоступен для создания и отправки. Токен не меняет сетевые разрешения.
4. В «Шаблоны» создайте шаблон типа «ВКонтакте» с текстом уведомления.
5. В «Каналы уведомлений» создайте канал типа «ВКонтакте». Укажите название,
   идентификатор сообщества, идентификатор получателя, токен и шаблон.
   Идентификатор сообщества — положительное число, без ссылки и префикса.
   Получатель — числовой идентификатор диалога (`peer_id`): для пользователя
   его идентификатор, для беседы `2000000000 + номер беседы`; отрицательное
   значение обозначает сообщество, если API допускает такой диалог.
6. Сохраните канал и нажмите «Проверить подключение». Проверка вызывает
   `groups.getTokenPermissions` и подтверждает право работы с сообщениями.
   Она не доказывает соответствие токена выбранному сообществу и доступ к
   получателю. Для этого выполните «Отправить тестовое уведомление».
7. Выберите канал в правиле обработки, эскалации или сводке.

Токен можно добавить позднее: сохранённый канал без токена или шаблона считается
не настроенным и не используется для отправки. Параметры подключения заполняет
администратор; готовых токенов, сообществ или получателей в поставке нет.

## Смена токена

Выпустите новый ключ, откройте канал, заполните поле «Токен доступа» и сохраните.
Пустое поле при редактировании сохраняет прежнее значение. Удаление выполняется
отдельной отметкой «Удалить сохранённый секрет». Сохранённый токен зашифрован,
API и интерфейс его обратно не возвращают; журнал аудита не содержит токен.
После проверки нового ключа отзовите старый во ВКонтакте.

Новые попытки используют актуальный токен. Уже начатая отправка может завершиться
со старым. Изменение сообщества или получателя останавливает отправку ранее
подготовленных уведомлений с другими параметрами; их нужно отдельно обработать.

## Доставка и ограничения

Токен передаётся в теле HTTPS POST, не в адресе запроса. Сервер API фиксирован;
переадресации не выполняются, сертификат и имя сервера проверяются, все ответы
DNS проверяются по списку разрешений. Разрешение ВКонтакте не разрешает остальные
публичные адреса. Приложение не устанавливает правила внешнего МСЭ.

Отправляется простой текст, без вложений и оформления HTML, не более 9000
единиц UTF-16 (символ вне основной плоскости, например некоторые эмодзи,
занимает две). Предпросмотр ссылок и упоминания отключены. Ограничение проверяется
при подготовке шаблона и непосредственно перед отправкой.

Ошибки API обрабатываются даже при HTTP 200. Ограничения частоты (6, 9, 29)
и временная ошибка сервера (10) допускают повтор по общей политике. Ошибки
авторизации, прав и запрета сообщений получателем требуют исправления настроек.
Пользователь получает безопасную русскую причину, без ответа API и токена.

`random_id` детерминированно вычисляется из идентификатора уведомления и
сохраняется при его повторных попытках. Это помогает API распознавать повторы,
но не гарантирует доставку строго один раз: пространство идентификаторов
ограничено, возможны коллизии и ограничения дедупликации на стороне ВКонтакте.
Неоднозначный сетевой результат отображается как неизвестный согласно общей
политике доставки. Коннектор использует существующие очереди и задержки повторов;
ограничение частоты на весь токен отдельно не реализовано. Пропускную способность
нужно проверять на разрешённом для вашего сообщества потоке.

Контракт сверяется с [официальной схемой messages.send](https://github.com/VKCOM/vk-api-schema/blob/master/messages/methods.json)
и [groups.getTokenPermissions](https://github.com/VKCOM/vk-api-schema/blob/master/groups/methods.json).
Проверки проекта используют локальный HTTPS-имитатор; реальная доставка требует
вашего токена и доступного сообщества.
