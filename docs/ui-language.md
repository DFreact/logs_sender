# Язык и терминология интерфейса

## Обязательные требования

Русский — язык по умолчанию и единственный доступный язык MVP. Переключатель
языка отсутствует. Это относится ко всем страницам, включая вход, восстановление
после ошибки, страницы отказа в доступе и недоступности приложения.

Локализуются кнопки, заголовки, меню, вкладки, подписи, подсказки, заполнители
полей, проверки ввода, уведомления, диалоги, формы, таблицы, фильтры, статусы,
пустые состояния, справка, доступные имена элементов, подписи графиков,
сообщения загрузки, пагинация, заголовок браузера и создаваемые системой отчёты.
Готовые компоненты и сообщения прокси также должны проходить проверку языка.

Внутренние API-поля, enum, имена классов и таблиц остаются английскими.
Пользователь не должен видеть их вместо понятной подписи. Содержимое полученных
событий, заданные пользователем названия, адреса, имена продуктов и протоколов
не переводятся автоматически. Такие данные отделяются от системных подписей.

## Статусы

Для каждой сущности используется собственное пространство ключей локализации.
Не преобразовывать enum заменой подчёркиваний и не показывать неизвестное
значение как запасную подпись.

| Событие | Подпись |
| --- | --- |
| NEW | Новое |
| ACKNOWLEDGED | Подтверждено |
| RESOLVED | Решено |
| SUPPRESSED | Подавлено |

| Уведомление | Подпись |
| --- | --- |
| PENDING | Ожидает отправки |
| PROCESSING | Обрабатывается |
| SENT | Отправлено |
| FAILED | Ошибка |
| RETRYING | Повторная попытка |
| CANCELLED | Отменено |

FAILED обозначает статус «Ошибка». Для отдельного сообщения о неудавшейся
отправке использовать «Ошибка доставки» с причиной и следующим действием.

| Важность | Подпись |
| --- | --- |
| DEBUG | Отладочная |
| INFO | Информационная |
| WARNING | Предупреждение |
| ERROR | Ошибка |
| CRITICAL | Критическая |
| null | Не задана |

| Режим отправки | Подпись |
| --- | --- |
| IMMEDIATE | Сразу |
| DELAYED | С задержкой |
| SCHEDULED | По расписанию |
| DIGEST | В составе сводки |

| Состояние системы | Подпись |
| --- | --- |
| HEALTHY | Работает |
| DEGRADED | Работает с ограничениями |
| UNAVAILABLE | Недоступно |
| UNKNOWN | Нет данных |

Для попыток отправки: PROCESSING → «Обрабатывается», SENT → «Отправлено»,
FAILED → «Ошибка», UNKNOWN → «Результат неизвестен».
Для настроек: enabled → «Включено», disabled → «Выключено»,
configured → «Настроено», not configured → «Не настроено»,
installed → «Установлено», visible → «Показывать в интерфейсе».

показывать пользователю. Добавление enum требует дополнения словаря до выпуска.

## Стиль, формы и подсказки

Писать кратко, спокойно и конкретно. Использовать обычный регистр предложений,
«ё» по правилам русского языка и кавычки «ёлочки». Заголовки и короткие подписи
без точки; полные предложения с точкой. Не писать «Успешно успешно выполнено».
Пример уведомления: «Правило сохранено».

Не использовать буквальный перевод: «Повторить отправку» вместо «Исполнить
повтор доставки», «Подтвердить» вместо «Подтвердить событие как увиденное»,
«Срок хранения» вместо «Политика удержания данных», «Канал уведомлений» вместо
«Поставщик уведомлений».

Каждое сложное поле имеет короткое пояснение под полем. Оно объясняет влияние
на работу, единицы и ограничения. Заполнитель не заменяет постоянную подпись.
Например:

- Поле: «Срок хранения событий»; единица: «дней».
- Подсказка: «После истечения этого срока события данного источника будут автоматически удаляться.»
- Проверка: «Укажите целое число дней больше нуля.»
- Поле: «Окно объединения повторов»; единица: «минут».
- Подсказка: «Одинаковые сообщения, полученные за это время, будут объединены в одно событие.»
- Поле: «Задержка эскалации».
- Подсказка: «Если событие не подтвердят за это время, уведомление будет отправлено по следующему каналу.»

Пустые состояния объясняют ситуацию и доступное действие: «Источников пока нет.
Добавьте источник, чтобы настроить обработку его событий». При фильтрации:
«События не найдены. Измените условия поиска или сбросьте фильтры».
Не предлагать действие, на которое у текущей роли нет прав.

## Ошибки и безопасная диагностика

Каждая ошибка сообщает, что произошло и что можно сделать. Не выводить напрямую
текст HTTP-ответа, detail от FastAPI/Pydantic, Error.message, исключения Python,
SQL, трассировку стека, имена контейнеров и внутренних сервисов или ответ
внешнего канала. Это распространяется на историю отправок, тест подключения,
предпросмотр, ошибки загрузки и неожиданные ошибки компонентов.

API возвращает стабильный код, разрешённые параметры и идентификатор обращения.
Предлагаемый контракт: `{code, params, field_errors: [{field, code, params}], request_id}`.
Коды и пути полей преобразуются в ключи локализации и русские подписи;
произвольный текст сервера не считается пользовательским сообщением.
HTTP-статус сам по себе не служит источником текста.

| Код | Сообщение пользователю |
| --- | --- |
| MAIL_CONNECTION_FAILED | Не удалось подключиться к почтовому серверу. Проверьте адрес сервера, порт и параметры авторизации. |
| DELIVERY_FAILED | Не удалось отправить уведомление. Проверьте настройки канала уведомлений и повторите отправку. |
| NETWORK_UNAVAILABLE | Не удалось связаться с приложением. Проверьте подключение к сети и повторите попытку. |
| VALIDATION_REQUIRED | Заполните это поле. |
| INVALID_CREDENTIALS | Не удалось войти. Проверьте имя пользователя и пароль. |
| ACCESS_DENIED | Недостаточно прав для этого действия. Обратитесь к администратору. |
| SESSION_EXPIRED | Сеанс завершён. Войдите снова. |
| RATE_LIMITED | Слишком много запросов. Подождите немного и повторите попытку. |
| RESOURCE_NOT_FOUND | Объект не найден. Обновите список и выберите другой объект. |
| VERSION_CONFLICT | Данные уже изменены другим пользователем. Обновите страницу и повторите изменения. |
| TEMPLATE_INVALID | Не удалось проверить шаблон. Проверьте переменные и синтаксис шаблона. |
| INTERNAL_ERROR | Не удалось выполнить действие. Повторите попытку позже. Если ошибка повторится, сообщите администратору номер обращения. |
| VALIDATION_ERROR | Не удалось сохранить данные. Проверьте значения полей и повторите попытку. |
| METHOD_NOT_ALLOWED | Это действие недоступно. Обновите страницу и повторите попытку. |
| REQUEST_TOO_LARGE | Не удалось обработать запрос: объём данных слишком большой. Уменьшите объём данных и повторите попытку. |
| SERVICE_UNAVAILABLE | Приложение временно недоступно. Повторите попытку позже. |

Если безопасный номер обращения отсутствует, общий текст заканчивается
«Если ошибка повторится, обратитесь к администратору» и не предлагает найти
несуществующий номер. Для сбоя отображения страницы: «Не удалось отобразить
страницу. Обновите её. Если ошибка повторится, обратитесь к администратору».

Неизвестный код, невалидный JSON, HTML-страница прокси и отсутствующее сообщение
отображаются через безопасный общий текст. Для неоднозначного результата
изменения после сетевого сбоя: «Не удалось получить результат действия.
Обновите данные, чтобы проверить, сохранились ли изменения».
Не предлагать повторную отправку, не предупредив о возможном повторном получении.

Параметры ошибок проходят белый список по коду; не принимать произвольные
сообщения через params. Тексты отображаются как текст, без HTML. Идентификатор
обращения генерируется приложением и не содержит данных пользователя.
Техническая диагностика доступна только в защищённых журналах: пароли, токены,
ключи, cookie, строки подключения и содержимое сообщений редактируются или
исключаются до записи. Проверять также вложенные исключения. Пользовательская
история отправок получает код и локализованную причину, а не журнал исключений.

## Архитектура локализации

Каталог первого этапа: `frontend/src/i18n/`. Реализован общий интерфейс
`useI18n()` с `t(key, params)`,
`formatDate`, `formatNumber` и форматированием количества. Каталог `ru` задаёт
тип ключей; компоненты не импортируют его напрямую. Другие языки впоследствии
подключаются через реестр каталогов и контекст без изменения компонентов.

Разделить словарь по областям: `common`, `navigation`, `auth`, `events`,
`sources`, `rules`, `channels`, `templates`, `notifications`, `digests`,
`users`, `audit`, `health`, `settings`, `validation`, `errors`.
Физически можно хранить несколько файлов в `locales/ru/`, но только этот
каталог является источником интерфейсных текстов. Статусы, роли, поля правил,
операторы и действия имеют явные отображения enum → ключ, без запасного
варианта с английским значением. Например, `events.status.NEW` → «Новое».

Запрещены русские и английские интерфейсные строки внутри React-компонентов,
вспомогательных функций и схем форм. Схемы проверок возвращают ключ и параметры.
Не собирать предложения конкатенацией; использовать полные переводимые фразы
с именованными параметрами. Учесть формы «1 событие», «2 события», «5 событий»,
«21 событие» через Intl.PluralRules. Даты и числа — через Intl с `ru-RU`,
часовой пояс — настройка установки/профиля с явным отображением там, где важен
момент отправки. В API хранить UTC и неизменяемые машинные значения.

На странице HTML установить `lang="ru"`. Локализовать title, aria-label,
alt, сообщения библиотек таблиц, календарей и диалогов. Для форм использовать
собственную доступную проверку с русскими сообщениями, чтобы язык браузера
не определял язык обязательных ошибок. Прокси-страницы и автономная страница
аварийного запуска получают тексты из каталога при сборке. Вне React допускаются
генерируемые артефакты, но не независимые копии переводов.

Системные шаблоны исходящих уведомлений по умолчанию русские. Их поставляемые
тексты централизованы; пользовательские шаблоны и исходное содержимое событий
являются данными и могут быть на другом языке. Технические переменные шаблонов
показывать только в редакторе, где они необходимы, с русскими описаниями.

В разработке отсутствующий ключ считается ошибкой; в сборке — блокирует выпуск.
В рабочем приложении неожиданное значение получает безопасную русскую подпись,
а диагностическое событие — код без содержимого пользовательских данных.
Резервного английского языка в MVP нет. Выбор библиотеки перевода остаётся
деталью реализации; перечисленные контракты обязательны при любом выборе.

## Недопустимые вставки и исключения

Запрещены системные подписи Events, Sources, Rules, Channels, Templates, Users,
Audit Log, System Health, Retry, Acknowledge, Resolved, Suppressed, Delivery Failed,
Loading, Submit, Save, Cancel, No data, Unknown, Error, Success, Dashboard, DLQ,
Worker и необработанные NEW/PENDING/FAILED. Использовать словарь выше.

Допустимы названия Telegram, Kaspersky, PostgreSQL, протоколы SMTP, HTTP, TLS,
форматы JSON, MIME, URL и IP-адреса там, где они нужны для настройки. Название
Webhook сопровождается пояснением «Отправка уведомлений на указанный адрес».
Не заменять понятное «Адрес сервера» внутренним `smtp_host`. Исключения
не разрешают английские подписи действий или статусов.

## Проверка и порядок изменений

Перед разработкой страницы прочитать этот документ. Новый термин сначала
добавляется сюда, затем в каталог. В проверке изменений контролировать:

1. Полноту переводов всех известных enum и кодов ошибок; неизвестные значения
   не раскрывают техническую строку.
2. Отсутствие интерфейсных литералов в JSX, атрибутах и вызовах уведомлений;
   статический анализ дополняется ручной проверкой, а не заменяет её.
3. Формы множественного числа, длинные русские подписи, даты и часовые пояса.
4. Вход, основные роли, пустые состояния, фильтры, ошибки форм и диалоги.
5. Ошибки API, прокси и внешних каналов, отсутствие сети и истёкший сеанс.
6. Ответ с намеренно вставленными SQL, трассировкой и тестовым секретом:
   они не появляются в интерфейсе, а секрет не попадает и в журнал.
7. Русские имена для средств доступности и отсутствие переключателя языка.

Приёмка каждого этапа интерфейса включает эти проверки. Один поиск латинских
букв недостаточен: в данных и названиях протоколов они законны.

## Пользователи и вход (этап 2)

Поля: «Имя пользователя», «Отображаемое имя», «Пароль», «Текущий пароль»,
«Новый пароль», «Повторите пароль», «Роль», «Учётная запись включена».
Статусы учётной записи: «Активна», «Отключена». Действия: «Создать пользователя»,
«Изменить пользователя», «Сменить пароль». Отдельная настройка языка отсутствует.

Подсказки: «От 3 до 64 символов: латинские буквы, цифры, точка, дефис и знак
подчёркивания»; «От 12 до 128 символов. Можно использовать пробелы»;
«Изменение роли, отключение учётной записи или смена пароля завершит её действующие сеансы».

| Код | Текст |
| --- | --- |
| CSRF_FAILED | Не удалось подтвердить действие. Обновите страницу и повторите попытку. |
| USERNAME_TAKEN | Это имя пользователя уже занято. Укажите другое имя. |
| LAST_ADMINISTRATOR | Нельзя отключить последнего администратора или изменить его роль. Сначала назначьте другого администратора. |
| PASSWORD_POLICY | Укажите пароль длиной от 12 до 128 символов. |
| PASSWORD_MISMATCH | Пароли не совпадают. Повторите новый пароль. |
| CURRENT_PASSWORD_INVALID | Текущий пароль указан неверно. Проверьте его и повторите попытку. |

Журнал аудита: «Вход выполнен», «Неудачная попытка входа», «Выход выполнен»,
«Пользователь создан», «Пользователь изменён», «Пароль изменён»,
«Первый администратор создан». Колонки: «Дата и время», «Пользователь»,
«Действие», «Объект», «Изменения», «IP-адрес». Неизвестное действие:
«Действие не определено». Технические ключи before/after не выводятся;
показываются только русские подписи разрешённых полей. Секреты и их хеши

## Доставка уведомлений (этап 8)

«Уведомления», «Неотправленные уведомления», «Подготовленное уведомление»,
«История попыток отправки», «Серия попыток», «Повторить отправку»,
«Отменить уведомление», «Отправить тестовое уведомление» — обязательные подписи.

понятно в карточке и в истории: что произошло, что проверить и как продолжить.
