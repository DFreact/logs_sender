# Права базы данных и доступ к секретам

Для новой установки используются отдельные роли PostgreSQL. Приём событий,
интерфейс и фоновые задачи работают без прав суперпользователя. Схема остаётся
на версии 0012; изменение относится к развёртыванию и обслуживанию.

| Роль | Назначение | Разрешения |
| --- | --- | --- |
| `eventhub` | Первоначальная настройка и резервное копирование | Администратор выделенного кластера; секрет только у PostgreSQL и одноразовой настройки |
| `eventhub_migrator` | Миграции и восстановление | Владелец схемы и объектов; создание объектов в одной БД, без суперпользователя, создания ролей/БД и обхода защиты строк |
| `eventhub_app` | Работа приложения | Чтение и изменение данных, использование последовательностей; без владения таблицами, изменения схемы, TRUNCATE и повышения прав |

Таблица версии миграций для приложения доступна только на чтение. Создание
временных таблиц и подключение приложения к служебной БД `postgres` запрещены.
Роли приложения и миграций не состоят в других ролях. Общедоступное создание
объектов в схеме закрыто. Расширение `pg_trgm` устанавливается ролью миграций
как доверенное расширение, без выдачи ей прав суперпользователя.

Пароли независимы, генерируются при установке и не передаются в аргументах
команд. Первоначальная настройка передаёт PostgreSQL проверочное значение SCRAM,
сформированное libpq; открытый пароль не включается в SQL. Ошибка настройки
не печатает пароль, строку подключения или содержимое исключения.

## Разделение секретов

| Компонент | Доступные секреты |
| --- | --- |
| API | Пароль приложения БД, пароль Redis, ключ сеансов, ключ каналов |
| Отправка уведомлений | Пароль приложения БД, пароль Redis, ключ каналов |
| Приём и обработка событий, обслуживание, публикация задач | Пароль приложения БД и пароль Redis |
| SMTP и планировщик | Только пароль приложения БД |
| PostgreSQL | Только административный пароль БД |
| Redis | Только пароль Redis |
| Веб-сервер и инициализация файлового хранилища | Нет секретов |
| Первоначальная настройка БД | Три пароля БД; задача завершается до запуска приложения |
| Миграции и восстановление БД | Только пароль роли миграций; одноразовые задачи |

У миграций и настройки БД нет тома с исходными сообщениями. Задача восстановления
не монтирует каталог данных PostgreSQL: она подключается по сети непосредственно
под ролью миграций. Её пароль находится в окружении только её короткоживущего
процесса; содержимое не выводится в команды Docker или журналы. Контейнеры не
получают сокет Docker или пространство процессов узла.

## Установка и восстановление

Перед миграциями выполняется одноразовая настройка ролей. Повторный запуск на
подготовленной установке допустим. При обнаружении таблиц другого владельца,
посторонних БД или неожиданных членств ролей настройка отказывает в запуске,
не преобразуя существующую установку автоматически.

При восстановлении сначала создаются роли. Затем дамп восстанавливается под
`eventhub_migrator`, с отказом от переноса старых владельцев и прав. Очистка
объектов выполняется **только в новой пустой установке**, которую создал инструмент;
существующие каталоги, проекты и тома он отвергает. После восстановления заново
назначаются права на существующие и будущие таблицы и последовательности.
Права проверяются до возобновления работы. Ключ каналов сохраняется, остальные
секреты, включая все пароли БД, создаются заново.

Права по умолчанию зависят от роли, создающей объекты, и сами по себе не меняют
существующие объекты — поэтому оба случая обрабатываются явно.
[Документация PostgreSQL](https://www.postgresql.org/docs/16/sql-alterdefaultprivileges.html).
Перенос владельцев и прав отключён параметрами восстановления;
[описание pg_restore](https://www.postgresql.org/docs/16/app-pgrestore.html).

Команда восстановления принимает копии своей версии. Для переноса копий
других версий требуется
отдельно проверенный перенос данных и назначение владельцев; запрещено просто
заменять Compose над старыми томами или вручную переписывать манифест копии.

## Границы защиты

Одна роль приложения пока используется всеми бизнес-процессами и может изменять
их общие таблицы. Это уменьшение инфраструктурных прав, а не изоляция компаний
или полная изоляция обработчиков друг от друга. Администратор узла Docker и
администратор PostgreSQL остаются доверенными. Резервные копии должны происходить
из доверенной установки и храниться на защищённом носителе.

Остаточные предупреждения
пакетов ОС, приёмка Astra и проверка реального MAX остаются отдельными задачами.

Для перехода 0.11.0 → 0.12.2 реализован отдельный перенос в новые тома:
[процедура](local-upgrade.md). Исходные владельцы и разрешения при импорте
не переносятся. Проверяются таблицы до/после миграции, файлы и секреты.
