# ADR-006: права PostgreSQL и разделение секретов

Статус: принято; реализовано в кандидате 0.12.1 для новых установок.
Дата: 6 октября 2026 года. Промышленная установка и приёмка Astra не выполнены.

## Причина

Приложение подключалось под ролью, созданной через POSTGRES_USER, то есть с правами
суперпользователя. Общие настройки контейнеров также передавали всем обработчикам
ключи сеансов и каналов. При компрометации одного обработчика это расширяло доступ
за пределы необходимой работы. Восстановление дампа без отдельного владельца
могло вернуть избыточные права даже после исправления обычного запуска.

## Решение

Разделить административную настройку, миграции и работу приложения на три роли.
Приложение получает доступ к данным без владения схемой и таблицами. Одноразовые
миграции владеют объектами, но не получают права администратора кластера.
Восстановление подключается непосредственно под ролью миграций; затем выдаются
права на существующие и будущие объекты. Таблица версии миграций доступна
приложению только на чтение. Пароли ролей независимы.

Ключ сеансов монтируется только в API; ключ каналов — в API и обработчик отправки.
Остальные процессы получают только необходимые им пароли БД и/или Redis.
Первоначальная настройка отказывает при чужом владельце таблиц, неожиданных
членствах ролей или посторонних БД. Она не является инструментом автоматического
преобразования существующего кластера.

Изменение прав выполняется при установке, миграции и восстановлении, а не
дополнительными запросами на пути каждого события. Расширение pg_trgm остаётся
доверенным расширением, устанавливаемым миграциями без суперпользователя.

## Последствия

Нужны дополнительные секреты и одноразовые задачи. Приёмка включает реальные
запреты DDL, TRUNCATE, чтения серверных файлов и повышения прав, а также
положительную проверку CRUD и последовательностей после восстановления.
Старые установки и копии не преобразуются заменой Compose: для них требуется
отдельно проверенный перенос. Пользовательские данные и текущий стенд не меняются.

Общая роль приложения сохраняет доступ к общим таблицам бизнес-процессов.
Разделение ролей по каждому обработчику и изоляция компаний этим решением
не реализованы. Администраторы ОС/Docker и PostgreSQL остаются доверенными.
